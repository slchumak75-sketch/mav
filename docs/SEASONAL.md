# Сезонный резерв и закупка — столбец 8

Столбец Excel «Минимальный резерв» **игнорируется** (старый J) и пустой столбец **H (8-й)** в новом файле используется для результата. Норма запаса считается из помесячных продаж.

## Что такое столбец 8

- В `Ведомость с периодом ОК (1).xlsx` столбец `H` (между `G = Конечный остаток` и `I = Цена последнего поставщика`) в исходнике был пустым — ни заголовка, ни значений (размеры колонки `width=10.5 style=21`).
- Теперь `H7 = "К закупке"` (sharedStrings) и `H8:H1857` — целое число «сколько докупить» на основании сезонной статистики.
- Заполнение делает `python3 tools/extract_xlsx.py --fill-purchase` (перезаписывает xlsx in-place, добавляет `H` в `sharedStrings.xml` и `sheet1.xml`, затем переупаковывает).
- Веб-приложение тоже считает `toPurchase` независимо (calc.js), но значения совпадают — тест `test_purchase_column_filled` сверяет заголовок H7 и что Excel-H совпадает с расчётом.

## Дата и горизонт

- Дата расчёта = `meta.periodTo` = **2026-10-19** (дата отчёта, `docProps/core.xml` modified `2026-10-19T21:03:26Z`; октябрь 2026 считается закрытым).
- По умолчанию горизонт **2 следующих календарных месяца**: ноябрь и декабрь 2026.
- Горизонт 1 / 2 / 3 / 4 / 6 мес. меняется в веб-UI «Настройка» и параметрами CLI `--horizon`.
- Буфер по умолчанию **10%**, меняется в UI и `--buffer`.

## Формулы (зеркало web/src/calc.js и tools/extract_xlsx.py)

```
typical[месяц] = среднее продаж этого календарного месяца в выгрузке
                 октябрь = среднее 4 наблюдений (2023, 2024, 2025, 2026) = (0+0+...)/4
                 ноябрь  = среднее 3 наблюдений (2023, 2024, 2025)
                 декабрь = среднее 3 наблюдений (2023, 2024, 2025)
                 январь  = среднее 3 наблюдений (2024, 2025, 2026) и т.д. (всего 37 мес L–AV)

сезонный_спрос = Σ typical[месяц] по месяцам горизонта
                 пример ноя+дек 2026: typical[11] + typical[12]

сезонный_резерв = ceil( сезонный_спрос × (1 + буфер%) )
                  буфер по умолчанию 10%

к_закупке = max(0, сезонный_резерв − конечный_остаток)
```

`minReserve` из xlsx в формулу не входит. `opening/incoming` в новом формате отсутствуют (0).

### Старый файл

- Те же формулы, но typical усредняет только 2 октября (окт 2025 и окт 2026), остальные месяцы — 1 наблюдение.

## Почему не σ по всем месяцам

У красок лето 20–27, зима 0–1. Общее СКО было бы «сезонностью в квадрате» и раздуло бы закупку зимой. Буфер — простой процент к спросу горизонта.

## Код

- Python: `tools/extract_xlsx.py` → `typical_by_calendar_month()`, `seasonal_plan_for_row()`, `fill_purchase_column()`.
- JS: `web/src/calc.js` → `typicalByCalendarMonth()`, `seasonalPlan()`, `withSeasonalPlan()`.
- Тесты: `web/src/calc.test.js`, `tests/test_extract.py::test_purchase_column_filled`.
- Параметры: `DEFAULT_AS_OF="2026-10-19"`, `DEFAULT_HORIZON_MONTHS=2`, `DEFAULT_BUFFER_PERCENT=10`.

UI не читает `item.minReserve` для статуса и отборов; читает `lastPrice/retailPrice/supplier` если есть.

## Как пересчитать вручную

```bash
python3 tools/extract_xlsx.py --fill-purchase --horizon 3 --buffer 20
# горизонт 3 мес (ноя, дек, янв) и 20% буфер → новые значения в H
python3 tools/extract_xlsx.py  # обновит JSON из нового xlsx
```

После этого веб-приложение и Excel показывают одинаковый столбец 8.

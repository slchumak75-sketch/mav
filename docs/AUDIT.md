# Аудит исходного файла «Ведомость мав.xlsx»

Дата проверки: 2026-10-19.

## Что это за «архив»

Файл `Ведомость мав.xlsx` — пакет Office Open XML (ZIP). Внутри 12 XML-частей,
без `vbaProject.bin`. Это выгрузка отчёта «Ведомость по остаткам ТМЦ на складах»,
не исходный код программы.

Автор в meta: Slava Chumak; последняя правка: «сидор Сидоров».
Приложение: Microsoft Excel 14. Лист: `Лист_1`. Размер области: `A1:W119`.

## Код / формулы

- Формул в ячейках: **0**.
- VBA / макросы: **нет**.
- Кнопки «Обновить» и «Настройка»: DrawingML-прямоугольники, `macro=""`.
  В Excel они ничего не делают.

## Целостность цифр

- Строк номенклатуры: **111** (Excel rows 8–118).
- Инвариант `начальный + приход − расход = конечный`: **111 / 111** сходятся.
- Единицы: банка 72, шт 34, ведро 5.
- Склад один, группа одна.
- Артикул заполнен у 1 позиции (`094977` — Краска ВД-АК-1035у белый Брава).

## Известный разрыв данных

Сумма помесячных колонок K–W **не равна** колонке «Расход» у 74 из 111 строк.
Это не ошибка парсера: в исходном xlsx лежат разные числа. Вероятно, месяцы —
отдельный разрез 1С (продажи / списания по периодам), а «Расход» — итог
движения за интервал отчёта. Приложение показывает оба факта и **не**
пересчитывает одно из другого.

## Мин. резерв

Колонка J «Минимальный резерв» в источнике есть, но **не является нормой
закупки**. Приложение её игнорирует и считает сезонный резерв / «к закупке»
из колонок K–W. См. `docs/SEASONAL.md`.

## Распаковка

`python3 tools/extract_xlsx.py` кладёт XML в `source/xlsx/` и пишет
`source/xlsx/MANIFEST.txt` (список частей + SHA-256 книги).

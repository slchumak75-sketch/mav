## Быстрый старт

```bash
python3 tools/extract_xlsx.py --fill-purchase  # заполнить столбец H в xlsx (опционально --horizon/--buffer)
python3 tools/extract_xlsx.py          # распаковать xlsx + JSON (авто-детект формата)
python3 -m unittest discover -s tests -v
cd web && npm ci && npm test && npm run build
cd web && npm run dev                  # http://0.0.0.0:5173
```

Или `make extract`, `make test`, `make build`, `make dev` (добавлен `make fill-purchase`).

### Сезонный план (кратко)

- `typical[месяц] = среднее продаж календарного месяца в выгрузке` (октябрь 2023–2026 = среднее 4 значений, ноябрь/декабрь 2023–2025 = среднее 3, и т.д.).
- `сезонный_спрос = Σ typical[месяц] по месяцам горизонта` (по умолчанию ноя+дек).
- `сезонный_резерв = ceil(спрос × 1.10)`, `к_закупке = max(0, резерв − конечный_остаток)`.
- Столбец `H` в xlsx — это `к_закупке`; фронт считает то же.

Если пользователь пришлёт новый xlsx:

1. Положить в корень (или заменить один из `XLSX_CANDIDATES`).
2. `python3 tools/extract_xlsx.py --fill-purchase` (если есть пустой H) или просто `python3 tools/extract_xlsx.py`.
3. Прогнать тесты. Если сменится число строк/месяцев — тесты уже гибкие, но проверить `A1:*` и `periodTo`.
4. Закоммитить xlsx, JSON, `source/xlsx/`, прогнать CI пушем.

## CI / автосборка

Файл: `.github/workflows/ci.yml`

- Триггеры: `push` (любая ветка), `pull_request`, `workflow_dispatch`.
- Job `build`: unpack+verify JSON (`--verify` требует что `data/vedomost.json` закоммичен), unittest, `npm ci`, vitest, `vite build`, артефакты `vedomost-site` и Pages.
- Job `deploy`: GitHub Pages после успешного push (`continue-on-error: true` — у токена может не быть прав включить Pages `gh api .../pages → 403`; сборка при этом зелёная).

После **любого** коммита в ветку GitHub сам запускает workflow. Локально Actions не запускаются — нужен `git push origin <ветка>`.

Чтобы сайт открылся на `https://slchumak75-sketch.github.io/mav/`:

1. Settings → Pages → Source: **GitHub Actions**
2. Повторный push (или Actions → CI → Re-run)

Права workflow: `contents: read`, `pages: write`, `id-token: write`.

Проверка прогона: `gh run list --branch <ветка>`, `gh run view <id>`.

## Что нельзя ломать

- Имена `Ведомость с периодом ОК (1).xlsx` / `Ведомость мав.xlsx` (кириллица). Парсер ищет их в `XLSX_CANDIDATES` с fallback на самый свежий `*.xlsx`.
- Логику сезонного резерва — не считать из `minReserve`, не путать `Расход` и `месячные продажи`.
- Помесячные колонки не пересчитывать из «Расхода» — разные факты 1С (828/1850 несовпадений — ожидаемо).
- `base: "./"` в Vite — сайт должен открываться и с GitHub Pages, и с превью.
- Столбец `H` нового файла — после `--fill-purchase` должен быть `К закупке`; тест сверяет заголовок и что H — числа.

## Как продолжать функционально

- Веб-UI: показывать поставщика/цены/склад в деталях, фильтр по поставщику, сводка по закупке в деньгах.
- Загрузка нового xlsx из UI (сейчас данные только из JSON на сборке).
- Другой горизонт по умолчанию (сейчас 2 мес. + 10% буфер) — уже настраивается.
- Закупка под весенний сезон уже зимой (сейчас берётся ближайший горизонт).
- Сравнение двух периодов / двух складов.
- Авторизация не нужна, пока это внутренняя ведомость.

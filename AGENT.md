# AGENT.md — как продолжить работу над МАВ

Документ для любого агента или человека, который подхватывает репозиторий.
Пишите сюда же, если меняете пайплайн, данные или CI.

## Состояние на 2026-10-19

Репозиторий `slchumak75-sketch/mav` содержал только `README.md` и файл
`Ведомость мав.xlsx` (это OOXML ZIP, не архив с исходниками). Кода приложения
не было: ни VBA, ни формул, ни скриптов.

Сделано в этой сессии (ветка `arena/feb459b3-mav`):

1. xlsx распакован в `source/xlsx/`.
2. Данные извлечены в `data/vedomost.json` (копия в `web/public/data/`).
3. Проверена целостность: 111 строк, баланс `начало + приход − расход = конец`
   сходится везде. VBA/формул нет. Помесячные колонки K–W **не** равны «Расход».
4. Собрано веб-приложение ведомости (`web/`).
5. GitHub Actions: `.github/workflows/ci.yml` — на **каждый push и pull_request**
   гоняет тесты и сборку, на push ещё публикует GitHub Pages.
6. Документация: этот файл, `README.md`, `docs/*`.

## Быстрый старт

```bash
python3 tools/extract_xlsx.py          # распаковать xlsx + JSON
python3 -m unittest discover -s tests -v
cd web && npm ci && npm test && npm run build
cd web && npm run dev                  # http://0.0.0.0:5173
```

Или `make extract`, `make test`, `make build`, `make dev`.

## Карта репозитория

```
Ведомость мав.xlsx          исходная ведомость (не удалять, не переименовывать без правки extract_xlsx.py)

data/vedomost.json          канонические данные для приложения и тестов

```

## Данные

- Лист: `Лист_1`, строки 8–118, 111 номенклатур.
- Склад: «Склад Кореличи». Группа: «2 краски растворители».
- Период в шапке: 01.10.25 — 19.10.26.
- Колонки: склад, группа, артикул, номенклатура, ед., нач. остаток, приход,
  расход, кон. остаток, мин. резерв, 13 месяцев (окт 2025 … окт 2026).
- Кнопки «Обновить» / «Настройка» в Excel — это фигуры DrawingML без макросов.
  В веб-приложении они работают.

Если пользователь пришлёт новый xlsx:

1. Заменить `Ведомость мав.xlsx` в корне.
2. `python3 tools/extract_xlsx.py`
3. Прогнать тесты. Если сменится число строк — поправить `LAST_DATA_ROW` и
   `test_item_count`.
4. Закоммитить xlsx, JSON, `source/xlsx/`, прогнать CI пушем.

## CI / автосборка

Файл: `.github/workflows/ci.yml`

- Триггеры: `push` (любая ветка), `pull_request`, `workflow_dispatch`.
- Job `build`: unpack+verify JSON, unittest, `npm ci`, vitest, `vite build`,
  артефакты `vedomost-site` и Pages.
- Job `deploy`: GitHub Pages после успешного push.

После **любого** коммита в ветку GitHub сам запускает workflow. Локально
Actions не запускаются — нужен `git push origin <ветка>`.

Если Pages не включён в настройках репозитория:

```
Settings → Pages → Source: GitHub Actions
```

или:

```
gh api repos/slchumak75-sketch/mav/pages -X POST -f build_type=workflow
```

Права: `contents: read`, `pages: write`, `id-token: write`.
Деплой Pages с не-default ветки работает, если source = GitHub Actions.

Проверка прогона: `gh run list --branch <ветка>`.

## Что нельзя ломать

- Имя исходного файла `Ведомость мав.xlsx` (кириллица). Парсер ищет его явно,
  с запасным вариантом «единственный *.xlsx в корне».
- Инвариант баланса. Если он разъедется — это ошибка данных, не «фича».
- Помесячные колонки не пересчитывать из «Расхода». Это разные факты 1С.
- `base: "./"` в Vite — сайт должен открываться и с GitHub Pages, и с превью.

## Как продолжать функционально

Имеет смысл следующим агентам:

- Загрузка нового xlsx из UI (сейчас данные только из JSON на сборке).
- Несколько складов/групп, когда они появятся в выгрузке.
- Редактирование мин. резерва и сохранение.
- Сравнение двух периодов.
- Авторизация не нужна, пока это внутренняя ведомость.
